# Measuring a type from its manufacturer's drawings

How the shapes in `shapes/` ([docs/SHAPES.md](../../docs/SHAPES.md)) are built from their manufacturers' documents.

A type's shape is read off the dimensioned side, plan and front views in its airport-planning document. A person
or agent places a few points on each outline. The software follows the drawn line between them, converts it to
meters and thins it to 1 cm. The judgment is which line is the outline. The drawing gives where it runs.

## Why points are placed by hand

A fully automatic line-follower worked on Boeing's 737 drawing and failed on Airbus's A320. At a junction it can't
tell a corner of the outline (the A320's windshield) from another part meeting it (the 737's winglet). Between two
points marked `"hidden"` the outline is bridged straight. They mark a nearer part in front, like the engine, the
wing-to-body fairing or a winglet across the crown. `snap.py` warns when a stretch leaves the drawn lines. That's
usually a point placed where the line is already hidden.

## The A320

Document: Airbus AC A320, Jul 01/26, from aircraft.airbus.com's Aircraft Characteristics page. The link changes
with each revision. The pages are 2-2-0 General Aircraft Dimensions, sharklet sheets 3 (page index 45) and 4 (46).
Not kept here.

```sh
T=tools/trace; W=/tmp/a320; mkdir -p $W
python -I $T/layers.py AC_A320.pdf 45 20 $W/side.png  --mode strokes-in-fill --clip 135,165,460,272
python -I $T/layers.py AC_A320.pdf 46 20 $W/plan.png  --mode strokes-in-fill --clip 145,215,470,515
python -I $T/layers.py AC_A320.pdf 45 20 $W/front.png --mode strokes-in-fill --clip 125,410,430,522
for v in side plan front; do python -I $T/snap.py $W/$v.png $T/a320/$v.anchors.json $W/$v.snap.json; done
python -I $T/features.py $W/side.png $W/side.snap.json $W/features.json
python -I $T/build.py $T/a320/recipe.json $W       # writes shapes/A320.json
python -I $T/smooth.py shapes/A320.json            # eases its lines
python -I $T/windshield.py shapes/A320.json        # the windshield's post on the outline, where it falls short
python -I $T/check.py $T/a320/recipe.json shapes/A320.json $W
```

`a320/recipe.json` holds the references in the rasters' pixels (line centers), the doors and cockpit panes picked
from `features.py`'s output and the printed dimensions to check. Result:

| fuselage width                 | 3.95 m   | 3.945 m (−0.1%) |
| wingspan                       | 35.80 m  | 35.57 m (−0.7%) |
| tailplane span                 | 12.45 m  | 12.54 m (+0.8%) |
| engine out from the centerline | 5.75 m   | 5.78 m (+0.5%)  |
| fin tip above the crown        | 5.87 m   | 5.84 m (−0.6%)  |

One scale serves all three views (the printed 37.57 m length), so the drawing's own small errors show. Its span is
0.7% short of the printed figure.

## The 737-800

Document: Boeing D6-58325-6, 2.2.12 General Dimensions, 737-800 with winglets (page index 42). It has the side, plan
and front views on one sheet. boeing.com serves HTML to scripts. A copy is at
`https://archive.aoe.vt.edu/mason/Mason_f/B737.pdf`.

```sh
T=tools/trace; W=/tmp/b738; mkdir -p $W
python -I $T/layers.py B737.pdf 42 12 $W/side.png  --mode fills --clip 135,370,510,500
python -I $T/layers.py B737.pdf 42 12 $W/plan.png  --mode fills --clip 135,60,510,256
python -I $T/layers.py B737.pdf 42 12 $W/front.png --mode fills --clip 140,505,500,660
python -I $T/layers.py B737.pdf 42 12 $W/glass.png --mode strokes --clip 135,370,510,500   # doors, cockpit panes
for v in side plan front; do python -I $T/snap.py $W/$v.png $T/b738/$v.anchors.json $W/$v.snap.json; done
python -I -c "from PIL import Image, ImageChops as C; C.darker(*(Image.open('$W/'+f).convert('L') for f in ('side.png','glass.png'))).save('$W/side_all.png')"
python -I $T/features.py $W/side_all.png $W/side.snap.json $W/features.json
python -I $T/build.py $T/b738/recipe.json $W       # writes shapes/B738.json
python -I $T/smooth.py shapes/B738.json            # eases its lines
python -I $T/check.py $T/b738/recipe.json shapes/B738.json $W
```

| Printed                        | Document | Shape           |
| ------------------------------ | -------- | --------------- |
| overall length                 | 39.47 m  | 39.50 m (+0.1%) |
| fuselage width                 | 3.76 m   | 3.80 m (+1.0%)  |
| wingspan                       | 35.79 m  | 35.72 m (−0.2%) |
| tailplane span                 | 14.35 m  | 14.44 m (+0.7%) |
| engine out from the centerline | 4.83 m   | 4.89 m (+1.3%)  |

Scaled by the printed 38.02 m fuselage length, with line centers as for Airbus. What's different on Boeing's sheet:

- **No cabin windows.** The recipe places them at the 737's 20 in (0.508 m) frame pitch, lined up on the overwing
  exits' windows. Their height comes from the exits. The shape says so in `cabin.windows.note`.
- **The engine's position** is printed to the nacelle's middle seen from above, so it's taken from the plan view's
  nacelle edges (`engine.outer`, `engine.inner`), not the front view's inlet (4.71 m).
- **The windshield** is bounded by the fuselage outline itself, so its pane is the outline's inner edge plus its two
  frame lines. The eyebrow windows are left out (plugged on later 737NGs).
- **"Approx 8 ft (2.44 m)"** in the front view is a horizontal distance, not the winglet's height.

Traced, the belly aft of the wing is up to 38 cm higher than the hand measurement this replaces.

## Placing points for a new type

1. Rasterize each view. Make grid crops of the parts (`grid.py`).
2. Per outline, place the start, every real corner, both ends of each hidden stretch, a few along long runs and the
   end. Name them as `build.py` reads them (`fuselage.crown`, `fin.leading`, `wing.upper` …). See `a320/` and
   `b738/`.
3. Snap, then fix any stretch it reports off the lines. Build, check and look at every view.

## The others

Each type's folder has its points (`*.anchors.json`) and `recipe.json`, whose `_about` names the document, page,
clips and any quirk. Rebuild as for the A320. Run `layers.py` per view with the clips the anchors' `_about` gives,
then `snap.py`, `features.py`, `build.py` and `check.py`.

`build.py` stretches each fuselage line's x to run from 0 to the length. That covers a line stopping a line's width
short, or a plan drawn a little short (the E175's by 1.2%). It also drops the steps back inboard that a pixel path
takes round a rounded tip. A freighter's recipe gives `windows` an empty range. `windows.x` lists them where they're
measured elsewhere (the A220s', on photos), with `"atExits": true` for one in the middle of each exit wherever it's
placed. `"clearOfDoors": true` leaves the placed windows out of the passenger doors and puts one in the middle of
each overwing exit, none between a pair side by side (the 737-7 and 737-10). Besides the core figures, `build.py`
checks the ones Boeing's plans print. Those are the wing tip's leading edge and chord (for the 717 its trailing edge
and the root's leading edge), the inlet's distance from the nose and the nacelle's width (with an `engine.inlet`
ring traced in the front view). They also include the overall length to whatever reaches furthest back (the 767's
is to its fin tip, the 717's to its tailplane's tips). It also checks heights above the crown that a recipe derives
from ground clearances (the fin's tip, the tailplane's tip, the nacelle's middle). `layers.py --mode fills` skips
white fills because the 767-300's sheet sits on a white panel.
